# v2-catalog — деплой

Сайт (`joma-retail.kz`) — это каталог CRM JOMA в новом дизайне. Единственный
источник данных о товарах/остатках — CRM (`GET /api/catalog`), см.
`CatalogClient.php`. Старый вручную забитый каталог удалён.

## Деплой через Plesk Git

Репозиторий: `https://github.com/uteshev007/joma-retail-site.git`, ветка
`v2-design` — в ней живёт актуальный сайт (в `main` остался старый
статический сайт + несвязанный `tg-sales-bot/`, её не трогаем).

В репозитории есть и другие папки не для этого сайта (`capi-worker/`,
`pdf-service/` — деплоятся отдельно). Поэтому в Plesk важно развести два пути:

1. **Websites & Domains → joma-retail.kz → Git** — подключить репозиторий,
   ветку `v2-design`. Plesk склонирует его в какую-то папку (например,
   `httpdocs` целиком) — это нормально, она не обязана быть публичным корнем.
2. **Websites & Domains → joma-retail.kz → Hosting Settings → Document root** —
   указать **подпапку `v2-catalog`** внутри склонированного репозитория
   (например `httpdocs/v2-catalog`), а не корень клона. Так наружу торчит
   только сайт, а `capi-worker/`, `pdf-service/`, `v2-prototype.html` и т.п.
   остаются вне веб-доступа.
3. После первого деплоя — создать `config.php` в папке `v2-catalog` **вручную**
   (через File Manager/SFTP), по образцу `config.example.php`, с реальными
   `crm_api_key`/`crm_lead_secret`. Этот файл в git не попадает
   (`.gitignore`) и не перезатирается при пуше.
4. `storage/` (кэш каталога и фото) создаётся автоматически при первом
   запросе — лежит на уровень выше `v2-catalog/` (вне публичного корня),
   права на запись веб-серверу нужны на родительскую папку репозитория.

## Настройка автодеплоя

В Plesk Git можно включить webhook от GitHub — тогда пуш в `v2-design`
обновляет сайт автоматически. Либо деплоить вручную кнопкой «Pull Updates»
в Plesk.
